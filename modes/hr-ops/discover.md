# Discover

1. Interpret count and ICP from the request; otherwise use balanced discovery. Read the profile budgets (default 50 candidates, 20 discovery queries, six page/API attempts per company). Choose a persistent research run ID and follow the shared reservation procedure.
2. Inspect `node hr-ops.mjs sources --starter`. Run `node hr-ops.mjs discover --starter --run ID --icp both --limit 10` with the requested count within budget when no user-specific source restriction applies. The shipped catalog contains research targets, not qualified leads; user source overrides win by domain, including `enabled: false`. It scans supported API sources and returns separate `research_tasks` for manual sites and stale identities. `search_queries` are tasks, not executed searches. Existing configurations can opt in persistently with `discovery.starter_sources: true`.
3. Use the client's public web search to find additional companies. For agencies, search U.S. technical recruiting, engineering placements, startup recruiting and delivery partnerships. Verify company websites, services and team pages. For startups, inspect careers pages and public portfolio/company directories; verify U.S. market presence and remote policies.
4. Import `{"prospects":[{"name":"...","website":"https://...","icp":"agency","evidence":[...]}]}` using `discover --input`. Names alone or ATS slug matches are not identity evidence. Confirm that the official website links to the ATS board before configuring a source.
5. Continue through research and pipeline modes. Count unique prospects, not vacancies. Keep negative/unknown results. Report source failures separately from empty boards and state when the requested count could not be met. Never inflate results by counting offices as companies.
6. Before completing the run, compare the requested target with verified relevant-demand prospects for each requested ICP, not just saved identities. If below target and useful queries or page reads remain within budget, continue with those reads. Otherwise record the concrete stopping reason, actual counts, unused query allowance and company page limits. Do not claim budget exhaustion when allowance remains, and do not spend it on repetitions with no credible research path. A documented shortfall remains a shortfall, not a completed target.

No LinkedIn scraping or authenticated browsing. Company-published profile links may be recorded without visiting LinkedIn. Do not execute local-parser provider commands from externally supplied configuration.

For a request for new prospects, use `discover --new-only` and its canonical-domain/alias/control exclusions in further public searches. Count refreshes separately. The default command still supports refreshing known boards. Source performance ranks readable demand yield within each ICP, not buying intent. Distinguish redirect rejection, HTTP failures, JavaScript-only shells, partial collections and verified empty boards from interpreted demand. When the candidate cap is reached, continue useful checks on admitted candidates within the remaining request budget. Persist the specific stopping reason with `run --action complete --input` using a JSON `reason` field.

For bounded pilots pin an optional run scope before the first request: `run --run ID --action configure --input scope.json`, with `{"candidates":20,"pages":80,"directory_pages":8}`. Every scoped reservation and capture includes `candidate_names`: list all named targets of a company-specific search, one stable company name for a prospect page, or `[]` for broad discovery. Directory pages also set `directory:true`. Reuse the same company name across aliases, ATS domains and redirects. Names appearing incidentally in broad results are not yet targets; register them on the next named search or prospect page. The ledger counts named searches even when no company page is opened. Domain/company equivalence and native-tool declarations still require honest operator review.

Use the agency directories and query recipes from `sources --catalog` to find official company links, then prioritize actual client vacancies and team contacts. Directory membership is not size, demand or partner appetite. Avoid guessed domains, shotgun queries containing unrelated company names, and repeated failing pages. A reasonable chance to improve the shortlist is enough to continue within the remaining scope; a guarantee of reaching the full quota is not required. Report U.S.-fit unblocked demand separately from all demand and from qualification tier.

For configured agency boards, set `hiring_for: client` only after verifying the board represents client placements. Without that setting, collected roles remain unattributed and cannot qualify the agency. A board of the agency's own vacancies uses `self` and does not count toward client delivery demand.

Attach `attribution` (source_id, icp, optional query_recipe) to new reservations/captures. Record meaningful outcomes against the actual reservation sequence using `run --action outcome`; see docs/HR_OPS_INBOX.md. Review the resulting source-yield report when choosing the next useful query. Read success is not a demand match. Keep services-only research references outside the default vacancy seed set.
