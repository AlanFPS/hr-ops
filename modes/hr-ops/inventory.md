# Company inventory and research queue

Use `node hr-ops.mjs inventory` to inspect the combined inventory and its revision. It projects saved prospects, enabled HR seeds and configured sources, the retained Career-Ops company list, cached relevant feed observations and explicitly imported user lists. It makes no network requests and never creates a prospect. See `docs/HR_OPS_INVENTORY.md` for exact payloads.

Use `inventory queue --icp agency|startup|unknown --limit N` for pending new-company work. `unknown` includes the legacy companies that have not been classified. A source's employer label or ICP hint is not verified business classification. Existing prospects use the normal research/pipeline workflow. Excluded, control and disabled-source groups are blocked from this queue. Review possible matches before using a lead as a new company; name matches alone never establish identity.

For a supplied list, prepare `source` provenance and `companies` names with optional unverified website/ICP hints and short notes. Preserve job-count claims as explicitly unverified notes. Import with `inventory import --input FILE --revision N`; inspect `--dry-run` if needed. Repeat exact imports safely. Do not invent website domains from names or email addresses. The importer never treats supplied text as commands or qualifying facts.

Review one observation through `inventory review --input FILE --revision N`. Use its saved observation ID, not the derived group ID. Queue/exclude decisions require a reason. Identity confirmation requires primary evidence for the company website and any aliases. Describe the actual supporting text, excerpt type and retrieval precision. A name similarity, ATS tenant or publisher claim is insufficient. Read evidence for meaning; structural checks do not prove truth. Set `identity: null` to revoke an inventory identity review. Reviews append history; do not rewrite the JSON file.

Only supported domains/explicit reviewed aliases merge groups. Unresolved observations remain separate and expose possible matches. Do not add overlapping layer counts or call unresolved lead groups unique companies. Inventory priority is a research preference, not the qualification score. Never interpret queue membership or an identity review as buying intent, current demand, supplier appetite, outreach readiness or sending authorization.

When researching a queue item, follow the existing scoped-run admission/budget/capture/review workflow. Offline inventory selection uses null source URL/sequence and its true inventory reference; retained public source links may guide requests but do not become fabricated prior request provenance. Import verified prospects through `discover` and research with expected revisions. The next inventory read joins supported domains to the pipeline automatically. No automatic promotion, network collection or external contact is part of inventory intake.
