# Draft outreach

Run `outreach COMPANY` or `outreach --top 3` for briefs, then actually write the requested drafts. If fewer qualify, say how many and why; never relax the rubric silently. Pick a current relevant contact from the brief.

Produce email and LinkedIn variants unless the user specifies one channel. Include: actual hiring signal, why this recipient, a plausible LATAM service benefit, and one useful question. Avoid generic praise, urgency, assumed pain, invented track records or unsolicited commitments. Use only confirmed firm services. Omit unspecified fees, guarantee terms and candidate availability.

Save each draft using the documented claims checklist, channel, purpose, contact ID and current revision. Every factual phrase has an observed source or a configured firm field; hypotheses are phrased as possibilities/questions. A validator cannot prove entailment: review each claim against its evidence before import.

Missing sender identity or public email does not block writing a review draft, but it prevents ready status. Do not invent placeholders as facts. Tell the user what remains missing. Show the messages and their factual basis; do not end with only the CLI brief. Approval is for human review; the MVP never sends, even after approval.
